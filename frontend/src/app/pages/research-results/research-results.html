RESEARCH AND EVIDENCE

Research Results

Findings from investigating GDELT as a data source for global news and public affairs intelligence.

Research summary

The current prototype demonstrates local data collection, ingestion and inspection while evaluating the suitability of GDELT for further analysis.

LOCAL DATA 287

Source files collected

The research dataset contains 95 Events files, 96 Mentions files and 96 GKG files.

INGESTION 442,720

Records imported

The local database contains records from all three dataset types, making them available for inspection without repeatedly querying the external API.

API TESTING HTTP 429

DOC API limitation encountered

Repeated rate-limit responses interrupted attempts to use the DOC API for exploratory queries. This limits its usefulness for the current testing workflow.

Data source evaluation

The investigation is assessing how different GDELT services could support the wider intelligence platform.

01

GDELT DOC API

Tested — limitation observed

The DOC API was tested with search and timeline queries. Repeated HTTP 429 responses occurred, including after waiting between requests. Further work is needed to determine whether a more controlled query strategy would be reliable enough.

02

GDELT BigQuery

Under investigation

BigQuery is being explored as an alternative route for querying GDELT data. Its suitability, access requirements, query costs and practical limits still need to be evaluated.

03

GDELT NGrams

Under investigation

NGrams are another avenue being considered for examining changes in language and topic frequency over time. Their usefulness for the project's intended research questions has not yet been established.

04

Local dataset ingestion

Demonstrated

Events, Mentions and GKG records have been imported into a local database. The prototype can inspect extracted source records, reducing dependence on live API calls during development and evaluation.

Research implications

What the current evidence means for the proposed platform.

Build around stored data

A local ingestion pipeline and database provide a foundation for repeatable queries, historical analysis and reducing dependence on live API availability.

Evaluate sources independently

Different GDELT services may serve different purposes. Each should be assessed for coverage, access restrictions, data structure and suitability for the intended features.

Move towards analysis

The next stage is to investigate how records can be connected across articles, events, people, organisations, locations and themes to support more useful research.

Interpreting these results

The record counts describe the locally collected research dataset, not the total volume of information available through GDELT. The DOC API observations describe the testing performed so far and do not establish that the service is universally unusable. BigQuery and NGrams remain under investigation until their behaviour has been tested and documented.
